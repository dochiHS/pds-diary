# Plan · Do · See — ALEPH T06 (플랜두씨 다이어리 1)

계획(Plan) → 실제로 한 일(Do) → 돌아보기(See)가 서버 데이터베이스로 이어지는 다이어리입니다.
체크만 하고 끝나는 할 일 앱이 아니라, **내가 계획을 어느 쪽으로 자주 틀리는지** 숫자와 근거 기록으로 보여 주는 것이 목적입니다.

> 지금은 로그인이 없어 링크를 아는 사람은 누구나 볼 수 있습니다. 남이 봐도 괜찮은 내용만 넣으세요.
> (잠그는 일은 T07에서 합니다.)

- 화면: GitHub Pages (`index.html` · `app.js` · `style.css` · `config.js`)
- 저장: Supabase(PostgreSQL, 서울 지역) — `supabase/schema.sql`
- DB 구조 문서: `contracts/pds-schema-v2.json`
- 외부 라이브러리 없음. 브라우저는 Supabase Data API의 함수(RPC)만 부릅니다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `index.html` | 첫 화면(맨 위 공개 안내), 보안 정책(CSP) |
| `app.js` | 화면 전부. 사용자 글자는 `textContent`로만 넣음 |
| `style.css` | 어두운 바탕·명조 제목 |
| `config.js` | Supabase **Project URL**과 **Publishable key**(공개용)만 |
| `supabase/schema.sql` | 표 6개·제약·트리거·RPC 함수·권한. SQL Editor에서 한 번 실행 |
| `contracts/pds-schema-v2.json` | 최종 DB의 표·항목·관계·날짜 규칙 |
| `.github/workflows/keepalive.yml` | 무료 프로젝트 일시정지 방지(하루 두 번 읽기 전용 호출) |
| `checks/` | 자동 검사 스크립트와 결과 |

## 설치 순서

1. **Supabase 프로젝트** — Free 요금제, 지역 Northeast Asia (Seoul).
2. **DB 만들기** — 대시보드 → SQL Editor → New query → `supabase/schema.sql` 전체를 붙여 넣고 Run.
   마지막 결과가 `rpc_functions_ready = 17`이면 성공입니다. 다시 실행해도 안전합니다.
3. **연결 값 넣기** — `config.js`에 다음 두 값을 넣습니다.
   - `SUPABASE_URL`: Project URL (`https://<프로젝트ID>.supabase.co`)
   - `SUPABASE_PUBLISHABLE_KEY`: Settings → API Keys의 Publishable key (`sb_publishable_…`)
   - **Secret key(`sb_secret_…`)·service_role 키는 절대 넣지 않습니다.** 넣으면 앱이 스스로 멈추고 경고를 띄웁니다.
4. **GitHub에 올리기** — 공개 저장소에 올리고 Settings → Pages → Branch `main` / `(root)`로 켭니다.
5. **keepalive 확인** — Actions 탭 → keepalive → Run workflow로 한 번 돌려 `200`이 나오는지 봅니다.

## 화면에서 하는 일

1. **계획** — 기간·우선순위·성공 기준·예상 시간. 고치면 판 번호가 오르고 고치기 전 판이 수정 이력에 남습니다(계획 ID는 그대로).
2. **할 일** — 만들기·고치기·완료·진행 중으로 되돌리기·지우기(되살리기 가능). 마감일·우선순위·태그·예상 시간.
   검색·거르기(상태·우선순위·태그)·정렬(정렬 기준과 같은 값일 때의 순서를 화면에 적어 둠).
3. **실행 기록** — 시작·끝(서울 시간)·실제로 걸린 시간·막혔던 이유를 할 일에 붙여 따로 저장. 저장 뒤 계획·할 일의 예상 값이 그대로인지 화면에 보여 줍니다.
4. **돌아보기** — 계획 수·완료 수·지연 수·막힘 수·예상 시간·실제 시간·차이. **숫자를 누르면 그 숫자가 나온 기록 목록**이 나오고, 기록을 누르면 그 할 일·실행 기록으로 이동합니다.
   고칠 점 한 줄을 저장해 **다음 계획으로 넘깁니다.**
5. **내보내기** — 맨 위 "내 자료 전체 내보내기"로 모든 표를 JSON 파일 하나로 받습니다.

## 규칙

- **시간대**: 날짜(`date`)는 서울 달력 날짜, 시각(`timestamptz`)은 절대 시각으로 저장하고 화면은 브라우저 시간대와 상관없이 **서울 시간(KST)**으로 보여 줍니다. '오늘'은 DB가 서울 기준으로 계산합니다.
- **단위**: 시간 값은 모두 **분** 단위 정수입니다.
- **지우기**: 할 일·실행 기록은 행을 남기고 `deleted_at`만 채웁니다. 집계에서는 빠집니다.
- **완료 중복 방지**: 같은 완료 요청은 같은 요청 키로 보내고, DB는 ① 요청 키 유일 제약 ② 할 일 하나에 살아 있는 완료 기록 1건(부분 유일 인덱스) ③ 할 일 행 잠금으로 막습니다. 버튼을 잠그는 방식에 기대지 않습니다.

돌아보기 숫자의 정의:

| 숫자 | 정의 |
|---|---|
| 계획 수 | 이 계획에 딸린, 지우지 않은 할 일 수 |
| 완료 수 | 그중 지금 완료 상태인 할 일 수 |
| 지연 수 | 완료되지 않았고 마감일이 오늘(서울)보다 앞선 할 일 수 (완료한 할 일은 세지 않음) |
| 막힘 수 | 막힌 이유가 하나라도 적힌 실행 기록이 있는 할 일 수 |
| 예상 시간 | 대상 할 일의 예상 시간 합계 |
| 실제 시간 | 대상 할 일의 실행 기록(취소한 기록 제외) 합계 |
| 차이 | 실제 시간 − 예상 시간 (아무것도 없으면 0) |

## 보안

- 모든 표에 RLS를 켜고 브라우저 역할(anon)에는 **표 권한을 주지 않습니다.** 브라우저는 `schema.sql`에서 연 함수 17개만 실행할 수 있습니다.
- 함수는 `security definer` + `search_path = ''`로 만들고, 도우미 함수는 노출되지 않는 `pds_private` 스키마에 둡니다.
- 브라우저에는 공개용 Publishable key만 두고, 비밀키는 코드·배포 파일·Git 기록 어디에도 두지 않습니다.
- `index.html`의 Content-Security-Policy로 같은 출처 스크립트만 실행하고, 연결은 같은 출처와 `*.supabase.co`로만 제한합니다.
- 로그인이 없으므로 링크를 아는 사람은 누구나 쓰고 지울 수 있습니다. 지운 할 일은 되살릴 수 있고, 계획 수정 이력은 지울 수 없습니다. 중요한 자료는 내보내기로 백업해 두세요.
